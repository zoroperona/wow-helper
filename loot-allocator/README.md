# WoW Loot Allocator

Local-first raid loot allocation workspace for season 12.1.

The application keeps its authoritative data in one SQLite file. The official
CN armory is the primary character source; DPSWOW is its fallback. Stat weights
can be generated by the local SimulationCraft CLI or imported from DPSWOW.
Allocation never depends on a live request.

## Development

Requires Node.js 22 or newer.

```bash
npm install
npx playwright install chromium
npm run dev
```

The default data file is `data/loot-allocator.sqlite`. Override it with
`LOOT_ALLOCATOR_DB`. The wow-db snapshot defaults to
`../wow-db/output/wow.sqlite`; override it with `WOW_DB_PATH`. The default
port is `5070`; override it with `PORT`.

The armory login uses a dedicated persistent Chromium profile at
`~/.wow-loot-allocator/armory-browser`. Override it with
`ARMORY_SESSION_PATH`. The profile contains Battle.net session cookies and
must not be shared or backed up. When the session expires, refreshing a
character opens the official armory page for an interactive login and resumes
automatically afterward.

## Scheduled simulation pipeline

The scheduled job refreshes each active character, runs the local
SimulationCraft CLI sequentially, and stores the result in the existing weight
cache. SimulationCraft support varies by specialization; unsupported runs are
recorded as failures without preventing tanks or healers from trying. Manual
DPSWOW imports remain available as a fallback for damage roles.

```bash
npm run build
npm run sim:daily
```

`SIMC_PATH` overrides the CLI path and `SIMC_RUNS_PATH` overrides the artifact
directory. Profiles, JSON, HTML, and SimC logs are retained under
`data/simc-runs/YYYY-MM-DD/`. Each artifact is named
`character-realm-YYYY-MM-DD-HH-MM-SS` using the Mac's local time.

The callable runner uses a guarded pipeline: acquire a single-run lock, build the
TypeScript output, validate SimC and both SQLite databases, back up the business
database, and attempt every active character. A character-level simulation
failure is recorded without preventing the remaining characters from running.
For cloud production, the application itself serves the frontend and read-only
API; GitHub Pages is not a production data source.

The production-safe runner is `scripts/run-daily-pipeline.mjs`. It performs the
build, dependency validation, business-database backup, DPSWOW-backed daily
simulation, and result status persistence. It does not publish a remote static
site. Merging official-armory equipment with cached DPSWOW talent data is a
separate local-first implementation change that is not implemented yet.

This repository does not install or require a local scheduler. Production
scheduling belongs to the remote deployment environment (for example Alibaba
Cloud cron or a managed scheduled task), which should invoke:

```bash
npm run ops:daily
```

Use `npm run ops:daily:check` for a no-write preflight. The legacy
`sim:daily:check` alias remains for compatibility and points to the same
production-safe runner. The misleading `sim:daily:publish` command has been
removed.

Set `SCHEDULED_TASK_EXPECTED=1` in that environment so the health endpoint warns
when the remote pipeline status is stale or missing.

Validate the complete task setup without backing up, simulating, or publishing:

```bash
npm run ops:daily:check
```

## wow-db handoff from the Windows game PC

The Windows machine with the updated CN WoW client generates the authoritative
snapshot and transfer package. After moving that zip to the Mac, first stop this
application, then validate and atomically import it:

```bash
npm run wowdb:import -- /path/to/wow-db-12.1.0.69299-cn-zhCN.zip --check-only
npm run wowdb:import -- /path/to/wow-db-12.1.0.69299-cn-zhCN.zip
```

The importer verifies the package identity, SHA-256, report failure count,
SQLite integrity, required tables, locale, and build monotonicity. It refuses to
replace a database that is open or has an unmerged WAL. The previous database is
retained under `../wow-db/output/archive/`; restart the application after import.

## Local static snapshot preview

The repository keeps a static snapshot builder for local inspection only. Remote
publication is disabled until the signed Draft Release ingress and pinned GitHub
Actions Pages workflow described in the implementation plan are complete.

Build and preview it locally:

```bash
npm run pages:build
npm run pages:preview
```

The preview is available at `http://127.0.0.1:5080`. Generated files are placed
in `pages-dist/` and are intentionally ignored by this source workspace.

No command in this workspace may push generated Pages content directly to a Git
repository. The current local-first plan runs the daily pipeline on the
administrator's machine. Historical cloud/systemd references are not active
deployment requirements.

## Current scope

- Season-aware roster management.
- Official CN armory lookup with interactive Battle.net session renewal.
- DPSWOW fallback when the official armory is temporarily unavailable.
- Manual DPSWOW stat-weight result link import.
- SimulationCraft stat-weight pipeline callable by the remote scheduler.
- Local latest-weight cache and portable JSON export.
- Tanks and healers can run local simulations and use successful results in ranking;
  manual DPSWOW stat-weight imports remain limited to damage roles.
- Boss loot allocation workspace with an explicit local `wow-db` catalog boundary.
- Season-aware pickup rules, allocation ledger, and per-player pickup totals.
- Trinket records are retained while remaining excluded from pickup totals by default.
- Separate allocation, roster, history, and rule configuration views.
